# Database Secrets Management

## Overview

The EcoVolt infrastructure uses AWS Secrets Manager for sensitive database credentials and AWS Systems Manager Parameter Store for non-sensitive configuration.

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    Database Credentials                      │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────────┐         ┌──────────────────┐         │
│  │  Secrets Manager │         │  SSM Parameter   │         │
│  │   (Sensitive)    │         │  Store (Public)  │         │
│  ├──────────────────┤         ├──────────────────┤         │
│  │ • Password       │         │ • Endpoint       │         │
│  │ • Full JSON      │         │ • Port           │         │
│  │   credentials    │         │ • Database name  │         │
│  │                  │         │ • Username       │         │
│  │ Auto-rotation:   │         │ • Connection str │         │
│  │ Every 30 days    │         │ • Secret ARN     │         │
│  └──────────────────┘         └──────────────────┘         │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## Secrets Manager (Sensitive Data)

### What's Stored

The database password and complete credentials are stored in AWS Secrets Manager:

```json
{
  "username": "ecovolt_admin",
  "password": "<auto-generated-32-char-password>",
  "engine": "postgres",
  "host": "ecovolt-dev-db.xxxxx.eu-central-1.rds.amazonaws.com",
  "port": 5432,
  "dbname": "ecovolt",
  "dbInstanceIdentifier": "ecovolt-dev-db"
}
```

### Secret Name

```
{project_name}-{environment}-rds-master-credentials
```

Examples:
- `ecovolt-dev-rds-master-credentials`
- `ecovolt-staging-rds-master-credentials`
- `ecovolt-prod-rds-master-credentials`

### Automatic Password Generation

Passwords are automatically generated using Terraform's `random_password` resource:
- **Length**: 32 characters
- **Character set**: Letters, numbers, and special characters
- **Excluded characters**: Characters that might cause issues in connection strings

### Automatic Rotation

Password rotation is **disabled by default** for dev/staging and can be enabled for production:

```hcl
# In terraform.tfvars
enable_secret_rotation = true  # Enable for prod
secret_rotation_days   = 30    # Rotate every 30 days
```

When enabled:
1. Lambda function creates a new password
2. Updates the RDS database
3. Tests the new password
4. Marks the new version as current
5. Old password remains accessible for 24 hours

## SSM Parameter Store (Non-Sensitive Data)

### Parameters Created

| Parameter | Value | Description |
|-----------|-------|-------------|
| `/{project}/{env}/database/endpoint` | `ecovolt-dev-db.xxxxx.rds.amazonaws.com` | RDS endpoint |
| `/{project}/{env}/database/port` | `5432` | Database port |
| `/{project}/{env}/database/name` | `ecovolt` | Database name |
| `/{project}/{env}/database/username` | `ecovolt_admin` | Master username |
| `/{project}/{env}/database/connection-string` | `postgresql://user:PASSWORD@host:port/db` | Connection template |
| `/{project}/{env}/database/secret-arn` | `arn:aws:secretsmanager:...` | Secret ARN reference |

### Why SSM for Non-Sensitive Data?

- **Cost**: SSM Standard parameters are free
- **Access**: Easier to access from Lambda, ECS, etc.
- **Versioning**: Built-in version history
- **No rotation needed**: These values don't change frequently

## Accessing Credentials

### From Lambda Functions

#### Get Full Credentials from Secrets Manager

```python
import boto3
import json

def get_db_credentials():
    client = boto3.client('secretsmanager')
    
    response = client.get_secret_value(
        SecretId='ecovolt-prod-rds-master-credentials'
    )
    
    return json.loads(response['SecretString'])

# Usage
creds = get_db_credentials()
connection_string = f"postgresql://{creds['username']}:{creds['password']}@{creds['host']}:{creds['port']}/{creds['dbname']}"
```

#### Get Individual Parameters from SSM

```python
import boto3

def get_db_config():
    ssm = boto3.client('ssm')
    
    params = ssm.get_parameters(
        Names=[
            '/ecovolt/prod/database/endpoint',
            '/ecovolt/prod/database/port',
            '/ecovolt/prod/database/name',
            '/ecovolt/prod/database/username'
        ]
    )
    
    config = {p['Name'].split('/')[-1]: p['Value'] for p in params['Parameters']}
    return config
```

#### Combined Approach (Recommended)

```python
import boto3
import json

def get_db_connection_string():
    """Get database connection string with password from Secrets Manager"""
    secrets = boto3.client('secretsmanager')
    ssm = boto3.client('ssm')
    
    # Get secret ARN from SSM (cached, fast)
    secret_arn_param = ssm.get_parameter(
        Name='/ecovolt/prod/database/secret-arn'
    )
    secret_arn = secret_arn_param['Parameter']['Value']
    
    # Get password from Secrets Manager
    secret = secrets.get_secret_value(SecretId=secret_arn)
    creds = json.loads(secret['SecretString'])
    
    # Get other config from SSM (cached, fast)
    params = ssm.get_parameters(
        Names=[
            '/ecovolt/prod/database/endpoint',
            '/ecovolt/prod/database/port',
            '/ecovolt/prod/database/name',
            '/ecovolt/prod/database/username'
        ]
    )
    
    config = {p['Name'].split('/')[-1]: p['Value'] for p in params['Parameters']}
    
    return f"postgresql://{config['username']}:{creds['password']}@{config['endpoint']}:{config['port']}/{config['name']}"
```

### From AWS CLI

#### Get Secret

```bash
# Get full secret
aws secretsmanager get-secret-value \
  --secret-id ecovolt-prod-rds-master-credentials \
  --query SecretString \
  --output text | jq .

# Get just the password
aws secretsmanager get-secret-value \
  --secret-id ecovolt-prod-rds-master-credentials \
  --query SecretString \
  --output text | jq -r .password
```

#### Get SSM Parameters

```bash
# Get single parameter
aws ssm get-parameter \
  --name /ecovolt/prod/database/endpoint \
  --query Parameter.Value \
  --output text

# Get multiple parameters
aws ssm get-parameters \
  --names \
    /ecovolt/prod/database/endpoint \
    /ecovolt/prod/database/port \
    /ecovolt/prod/database/name \
  --query 'Parameters[*].[Name,Value]' \
  --output table
```

## Password Rotation

### How It Works

1. **Create**: Lambda generates a new password
2. **Set**: Lambda updates the RDS password
3. **Test**: Lambda tests the new password
4. **Finish**: New password becomes current

### Enable Rotation

```hcl
# In environments/prod.tfvars
enable_secret_rotation = true
secret_rotation_days   = 30
```

### Manual Rotation

```bash
# Trigger immediate rotation
aws secretsmanager rotate-secret \
  --secret-id ecovolt-prod-rds-master-credentials
```

### Rotation Lambda

The rotation Lambda function:
- Runs in the same VPC as RDS
- Has access to the database security group
- Uses psycopg2 to connect to PostgreSQL
- Follows AWS best practices for rotation

## Security Best Practices

### ✅ Do's

1. **Use Secrets Manager for passwords**
   - Automatic rotation
   - Encryption at rest
   - Audit logging

2. **Use SSM for non-sensitive config**
   - Free for standard parameters
   - Easy to access
   - Version history

3. **Enable rotation in production**
   - Reduces risk of compromised credentials
   - Automated process

4. **Use IAM policies for access control**
   - Least privilege principle
   - Separate dev/staging/prod access

5. **Monitor secret access**
   - CloudTrail logs all access
   - Set up alarms for unusual access

### ❌ Don'ts

1. **Don't hardcode passwords**
   - Never in code
   - Never in tfvars files
   - Never in environment variables

2. **Don't share credentials**
   - Each environment has its own
   - Use IAM roles instead

3. **Don't disable encryption**
   - Always use KMS encryption
   - Use customer-managed keys for prod

4. **Don't skip rotation in production**
   - Enable automatic rotation
   - Test rotation process

## Troubleshooting

### Can't Access Secret

**Error**: `AccessDeniedException`

**Solution**: Check IAM permissions
```bash
aws iam get-role-policy \
  --role-name your-lambda-role \
  --policy-name your-policy
```

### Rotation Failed

**Error**: `Rotation failed`

**Solution**: Check Lambda logs
```bash
aws logs tail /aws/lambda/ecovolt-prod-rotate-rds-secret --follow
```

### Connection Failed After Rotation

**Error**: `Authentication failed`

**Solution**: Applications may be caching old credentials
1. Restart applications
2. Check secret version being used
3. Verify rotation completed successfully

## Migration from Hardcoded Passwords

If you have existing databases with hardcoded passwords:

1. **Deploy the new infrastructure** (creates secret with new password)
2. **Update RDS password manually** to match the generated one:
   ```bash
   NEW_PASSWORD=$(aws secretsmanager get-secret-value \
     --secret-id ecovolt-prod-rds-master-credentials \
     --query SecretString --output text | jq -r .password)
   
   aws rds modify-db-instance \
     --db-instance-identifier ecovolt-prod-db \
     --master-user-password "$NEW_PASSWORD" \
     --apply-immediately
   ```
3. **Update applications** to use Secrets Manager
4. **Enable rotation** after verification
